# DMAC PL080 双AHB架构与通道回退机制详解

## 1. Surya芯片的DMAC PL080硬件架构

### 1.1 关键硬件参数

根据 [dma.h](surya_recovery/sdk/arm/indie/surya/include/silicon/sfr/dma.h) 的寄存器定义：

```c
// PERIPHID3 寄存器（0x0EC）
typedef struct
{
    uint32_t CHANNELS      : 3;  // 通道数
    uint32_t MASTERS       : 1;  // AHB Master数量 ← 关键！
    uint32_t BUSWIDTH      : 3;  // 总线宽度
    uint32_t SRCRQSTRS     : 1;  // DMA源请求者数量
} PERIPHID3_t;
```

**Surya配置**：
- **16个DMA通道** (CHANNELS = 4 → 2^4 = 16)
- **2个AHB Master端口** (MASTERS = 1)
- **AHB总线宽度**：32位
- **支持的外设请求源**：多个

### 1.2 两路AHB Master架构

```
┌──────────────────────────────────────────────────────┐
│           DMAC PL080 控制器                           │
│                                                       │
│  ┌────────────────────────────────────────────────┐  │
│  │  16个DMA通道（Channel 0-15）                   │  │
│  │  ┌──────────────────────────────────────────┐  │  │
│  │  │ 每个通道配置：                            │  │  │
│  │  │ - SRC_MASTER_SEL (1 bit)  ← AHB M1/M2选择│  │  │
│  │  │ - DEST_MASTER_SEL (1 bit) ← AHB M1/M2选择│  │  │
│  │  └──────────────────────────────────────────┘  │  │
│  └────────────────────────────────────────────────┘  │
│                     │                                 │
│    ┌────────────────┼────────────────┐               │
│    ▼                ▼                ▼               │
│  ┌──────────┐  ┌──────────┐    [通道控制]           │
│  │AHB M1    │  │AHB M2    │                         │
│  │(Master 1)│  │(Master 2)│                         │
│  └──────────┘  └──────────┘                         │
│    ↓            ↓                                    │
└────┼────────────┼─────────────────────────────────────┘
     │            │
     ▼            ▼
  [AHB总线上的不同外设/内存映射区域]
  
  M1可能连接到：SRAM, 某些外设
  M2可能连接到：DRAM, 其他外设
```

### 1.3 通道配置中的AHB Master选择

```c
// DMA_CH_CTRL_t 结构（每个通道的控制寄存器）
typedef struct
{
    // ...其他字段...
    uint32_t SRC_MASTER_SEL    : 1;  // 源地址使用AHB Master
    uint32_t DEST_MASTER_SEL   : 1;  // 目标地址使用AHB Master
    // ...其他字段...
} DMA_CH_CTRL_t;

// 含义：
// SRC_MASTER_SEL = 0  → 源使用 AHB Master 1
// SRC_MASTER_SEL = 1  → 源使用 AHB Master 2
// 
// DEST_MASTER_SEL = 0 → 目标使用 AHB Master 1
// DEST_MASTER_SEL = 1 → 目标使用 AHB Master 2
```

## 2. 为什么是两路AHB而不是四路？

### 2.1 PL080标准规范

ARM的DMAC PL080是业界标准的通用DMA控制器，其设计特点：

| 特性 | 说明 |
|------|------|
| **AHB Master数量** | 固定为2个（这是PL080的标准配置） |
| **AHB Slave数量** | 可配置（通常1个用于寄存器访问） |
| **通道数** | 可配置（常见：4, 8, 16个） |
| **外设请求线** | 可配置（通常4-16条） |

**为什么只有2个Master？**
- ARM设计的通用标准，平衡了成本和功能
- 2个Master足以支持高性能DMA操作
- 源和目标可同时使用不同的Master并行访问不同总线

### 2.2 Surya芯片采用PL080的原因

```
PL080配置选择：
┌─────────────────────────────────┐
│ Surya芯片设计决策                │
├─────────────────────────────────┤
│ ✓ 通道数：16个                  │
│   → 支持多个DMA请求源           │
│                                 │
│ ✓ AHB Master：2个               │
│   → 支持并行访问2条不同的总线   │
│                                 │
│ ✓ 总线宽度：32位                │
│   → 与Surya系统架构匹配         │
└─────────────────────────────────┘
```

### 2.3 两路AHB的物理映射

```
Surya系统内存地址空间：

0x0000_0000
    │
    ├─ AHB Master 1 访问范围
    │  ├─ SRAM 区域 (低延迟)
    │  │  └─ RXC0/RXC1 数据缓冲
    │  │     ├─ src_ch0 (RXC0 接收链路)
    │  │     └─ src_ch2 (RXC1 接收链路)
    │  │
    │  └─ 部分外设 (低延迟要求)
    │
0x4000_0000 (分界)
    │
    ├─ AHB Master 2 访问范围
    │  ├─ DRAM 区域 (高容量)
    │  │  ├─ chirp_buffer[4]
    │  │  ├─ mag2_acc[4]
    │  │  └─ raw_fft_data
    │  │
    │  └─ 其他外设
    │
0xFFFF_FFFF
```

## 3. 通道回退与双AHB的直接关系

### 3.1 问题根源：4个BBE vs 2个AHB Master

```
理想情况（如果有4个AHB Master）：
BBE#0 ← AHB M1 ← src_ch0
BBE#1 ← AHB M2 ← src_ch1  ✗ 但src_ch1不存在！
BBE#2 ← AHB M3 ← src_ch2
BBE#3 ← AHB M4 ← src_ch3  ✗ 但src_ch3不存在！

实际硬件（只有2个AHB Master）：
BBE#0 ─┐
       ├─ AHB M1 ─── RXC0链路 ─── src_ch0 (SRAM)
       │
BBE#1 ─┘  ← 被迫共享src_ch0（回退）

BBE#2 ─┐
       ├─ AHB M2 ─── RXC1链路 ─── src_ch2 (SRAM)
       │
BBE#3 ─┘  ← 被迫共享src_ch2（回退）
```

### 3.2 硬件拓扑详解

```
┌────────────────────────────────────────────────────────┐
│         Surya SoC 系统总线架构                          │
└────────────────────────────────────────────────────────┘
                  │
        ┌─────────┴─────────┐
        ▼                   ▼
    [AHB Bus #1]      [AHB Bus #2]
    (低延迟)          (一般性)
        │                   │
    ┌───┴────┐          ┌───┴────┐
    ▼        ▼          ▼        ▼
  SRAM    外设0      DRAM      外设1
   │                  │
   ├─ RXC0缓冲       ├─ chirp_buffer
   │  └─src_ch0      │
   │                 └─ mag2_acc
   └─ RXC1缓冲
      └─src_ch2

DMAC PL080 通道配置：
┌─────────────────────────────────────────┐
│ 16个通道，每个可独立选择AHB M1或M2      │
├─────────────────────────────────────────┤
│ 通道0-7  (偶数通道)                     │
│   配置为：SRC_MASTER_SEL=0 (M1)        │
│   → 从SRAM (src_ch0)读取                │
│                                        │
│ 通道8-15 (奇数通道)                    │
│   配置为：SRC_MASTER_SEL=1 (M2)        │
│   → 从DRAM (chirp_buffer)读取/写入     │
└─────────────────────────────────────────┘

关键理解：
- src_ch1 和 src_ch3 根本不存在于任何AHB总线上
- 即使加入第3和第4个AHB Master，SRAM中也没有这些缓冲区
- 问题不仅仅是"AHB Master不足"，而是"物理数据源不存在"
```

### 3.3 回退的必然性

```
配置流程：

1️⃣ DMABufferConfigComplexMode(bbe_id=1, ...)
          │
          ▼
2️⃣ switch(1) → case 1
          │
          ▼
3️⃣ 寻找 src_ch1
          │
          ├─ 在SRAM中查找？ ❌ 不存在
          ├─ 在DRAM中查找？ ❌ 不存在
          ├─ 在任何总线上查找？ ❌ 完全不存在
          │
          ▼
4️⃣ 决策：无法找到真实数据源
          │
          ├─ 选项A：返回Error → 但这会导致BBE#1无法启动
          │
          ├─ 选项B：使用近似替代 → 回退到src_ch0
          │         (当前实现)
          │         风险：两个BBE处理相同数据
          │
          └─ 选项C：等待SYSMEM实现 → 未来方案
```

## 4. 两路AHB的带宽影响

### 4.1 并行传输能力

```
场景A：BBE#0和BBE#1都使用AHB M1（回退情况）
┌────────────────────────────────────┐
│  时刻T0-T3                         │
├────────────────────────────────────┤
│                                    │
│ AHB M1总线                        │
│ ├─ BBE#0 DMA: 读src_ch0 [50%带宽]│
│ └─ BBE#1 DMA: 读src_ch0 [50%带宽]│ ← 竞争！
│                                    │
│ 实际吞吐量 ≈ 理论值 (但有竞争)    │
│                                    │
└────────────────────────────────────┘

场景B：理想情况（两个独立源）
┌────────────────────────────────────┐
│  时刻T0-T3                         │
├────────────────────────────────────┤
│                                    │
│ AHB M1总线              AHB M2总线 │
│ ├─ BBE#0/BBE#1 DMA  ├─ 其他设备访问│
│   读src_ch0         读DRAM         │
│   (100%M1带宽)      (100%M2带宽)   │
│                                    │
│ 真正的并行，零竞争                 │
│                                    │
└────────────────────────────────────┘
```

### 4.2 带宽计算

```
AHB M1总线：
├─ 位宽：32位
├─ 频率：假设100MHz
├─ 理论带宽：32 × 100M / 8 = 400 MB/s
│
└─ 实际分配：
   ├─ BBE#0 + BBE#1 DMA：需要 200 MB/s (估计)
   ├─ RXC0接收缓冲更新：需要 100 MB/s (估计)
   └─ 其他外设访问：需要 50 MB/s (估计)
   ─────────────────────────
   总需求：350 MB/s < 400 MB/s ✓ (勉强满足，有竞争)

AHB M2总线：
├─ 相同的物理特性
└─ 主要用于：DRAM访问、输出缓冲写入

结论：
两路AHB虽然物理上独立，但由于src_ch1/ch3不存在，
BBE#1和BBE#3被迫共享M1和M2，导致带宽竞争
```

## 5. 为什么不在DRAM中创建src_ch1/ch3？

### 5.1 技术限制

```
不可行原因：

1️⃣ 接收链路物理约束
   RXC0 ← 天线信号 ← ADC#0
   RXC1 ← 天线信号 ← ADC#1
   ─────────────────────
   → 只有2条ADC链路
   → 只能产生2个数据源
   → 即使在DRAM中创建缓冲，也无数据填充

2️⃣ SRAM内存布局固定
   .sram.rxc0_ds0 → src_ch0
   .sram.rxc1_ds0 → src_ch2
   ─────────────────────
   → 这些是硬件设计时确定的内存映射
   → 不能动态改变

3️⃣ 时延要求
   RXC数据流 → 必须立即缓冲到低延迟SRAM
   ─────────────────────────────────────
   → DRAM访问延迟太高（~50-200ns vs SRAM ~5-10ns）
   → 无法满足实时接收要求
```

### 5.2 理想与现实的差距

```
理想设计（成本无限制）：
┌─────────────────────┐
│ 4条ADC接收链路      │
└─────────────────────┘
    │  │  │  │
    ▼  ▼  ▼  ▼
   [4个SRAM缓冲区]
    ├─ src_ch0
    ├─ src_ch1 ← 理想
    ├─ src_ch2
    └─ src_ch3 ← 理想
    │  │  │  │
    ▼  ▼  ▼  ▼
   [4个BBE处理引擎]
    ├─ BBE#0
    ├─ BBE#1
    ├─ BBE#2
    └─ BBE#3

实际设计（成本优化）：
┌──────────────────┐
│ 2条ADC接收链路   │
└──────────────────┘
    │  │
    ▼  ▼
   [2个SRAM缓冲区]
    ├─ src_ch0 (RXC0)
    └─ src_ch2 (RXC1)
    │  │
    └──┴─────────┐
       │         │ ← 必须共享或回退
       ▼         ▼
    [4个BBE处理引擎]
    ├─ BBE#0
    ├─ BBE#1 ← 无独立源，回退到ch0
    ├─ BBE#2
    └─ BBE#3 ← 无独立源，回退到ch2
```

## 6. 两路AHB如何解决这个问题？

### 6.1 理论上的解决方案

```
如果增加AHB Master到4个：

┌──────────────────────────────────┐
│ 4个AHB Master × 2个SRAM源 = 不匹配│
├──────────────────────────────────┤
│ AHB M1 ← src_ch0                 │
│ AHB M2 ← src_ch2                 │
│ AHB M3 ← ??? (无数据源)          │
│ AHB M4 ← ??? (无数据源)          │
└──────────────────────────────────┘

结论：增加AHB Master不能解决问题，除非同时增加ADC和SRAM
```

### 6.2 真正的解决方案：SYSMEM映射

```
当前代码注释提示：
// Src address should be SYSMEM

方案：使用系统内存（DRAM通过AHB M2访问）

┌─────────────────────────────────────┐
│ 改进设计                             │
├─────────────────────────────────────┤
│ AHB M1              AHB M2          │
│ ├─ src_ch0        ├─ src_ch1_sys   │
│ │  (SRAM RXC0)    │  (DRAM)        │
│ │                 │                │
│ └─ BBE#0,#1处理   └─ BBE#1从       │
│    (来自M1)          DRAM读取      │
│                      (来自M2)      │
│                                    │
│ AHB M2继续处理：               │
│ ├─ 输出缓冲写入（DRAM）         │
│ ├─ src_ch1_sys读取             │
│ └─ 负载均衡                     │
└─────────────────────────────────────┘

优点：
✓ 最大化利用2个AHB Master
✓ BBE#1从DRAM读取，而不是重复读SRAM
✓ M1/M2流量分散，减少竞争

缺点：
✗ DRAM延迟更高（但相比SRAM延迟差异不会导致失败）
✗ M2带宽需要承载更多流量
```

## 8. 关键结论

### 8.1 回退原因梳理

| 层级 | 原因 | 解决方案 |
|------|------|--------|
| **物理层** | 只有2条ADC接收链路 | 无法改变（硬件设计已定） |
| **SRAM层** | 未定义src_ch1/ch3缓冲区 | 需要在DRAM中创建（SYSMEM） |
| **AHB层** | 2个Master不足以独立驱动4个BBE | 改进为多源DRAM映射 |
| **软件层** | 代码隐式回退而不是显式处理 | 添加错误处理和SYSMEM映射 |

### 8.2 两路AHB的实际意义

```
AHB M1 (32位) ←→ SRAM区域 (src_ch0, src_ch2)
               ↑
               低延迟（~5-10ns）
               ← 用于实时接收数据

AHB M2 (32位) ←→ DRAM区域 (输出缓冲、中间结果)
               ↑
               相对延迟（~50-200ns）
               ← 用于一般处理和输出

两路并行：
• M1和M2可同时工作，互不阻塞
• 但目前的软件设计未充分利用这一优势
• 原因：src_ch1/ch3缺失导致被迫共享M1
```

### 8.3 改进建议

**短期（立即）**：
```c
// 添加警告注释和日志
case 1:
    // ⚠️ FALLBACK: src_ch1不存在，回退到src_ch0
    // 这会导致BBE#0和BBE#1竞争AHB M1带宽
    // TODO: 实现SYSMEM映射方案
    fprintf(stderr, "[DMA] WARNING: BBE#1 fallback to src_ch0\n");
    src_addr = (Addr_t) (&src_ch0[0]);
    break;
```

**长期（计划）**：
```c
// 实现SYSMEM映射
case 1:
    // 使用系统内存中的数据源
    src_addr = (Addr_t) (&src_ch1_sysmem[0]);  // DRAM中的新缓冲
    src_meta_addr = (Addr_t) &src_meta_ch1_sysmem[0];
    // 这样BBE#1使用AHB M2，减少M1竞争
    break;
```
