## 2. DSP处理子系统详解（4个BBE）

### 2.1 BBE处理引擎架构

```
每个BBE都是独立的Tensilica Xtensa LX处理器：

┌────────────────────────────────────────────┐
│ BBE#i (i=0,1,2,3)                         │
├────────────────────────────────────────────┤
│                                            │
│ ┌──────────────────────────────────────┐  │
│ │ 处理器核心                            │  │
│ │ ├─ Xtensa ISA (指令集)               │  │
│ │ ├─ 频率: ~200MHz                     │  │
│ │ ├─ 寄存器文件 (32x32位)             │  │
│ │ ├─ ALU/乘法器                       │  │
│ │ └─ 访问控制单元                     │  │
│ └──────────────────────────────────────┘  │
│                                            │
│ ┌──────────────────────────────────────┐  │
│ │ 专用硬件加速器                        │  │
│ ├─ iDMA (智能DMA)                      │  │
│ │  ├─ 描述符链支持                     │  │
│ │  ├─ 链式触发                         │  │
│ │  └─ 圆形缓冲支持                     │  │
│ ├─ FFT加速器 (可选)                    │  │
│ └─ 乘法器阵列 (MAC)                    │  │
│                                            │
│ ┌──────────────────────────────────────┐  │
│ │ 内存层次                              │  │
│ ├─ L1指令缓存 (I-cache)                │  │
│ ├─ L1数据缓存 (D-cache)                │  │
│ ├─ L2统一缓存 (可选)                   │  │
│ └─ 本地指令/数据存储 (XLMI)           │  │
│                                            │
│ ┌──────────────────────────────────────┐  │
│ │ 外部接口                              │  │
│ ├─ AHB总线接口 (M1或M2)               │  │
│ ├─ DMA请求线 (中断/触发)             │  │
│ ├─ IPC通信区 (0x60000000 + 2k*i)     │  │
│ └─ 时钟/复位控制                      │  │
│                                            │
└────────────────────────────────────────────┘
```

### 2.2 4个BBE的独立性和共享资源

```
独立资源（每个BBE有自己的）：
├─ 处理器核心（寄存器、ALU等）
├─ L1缓存（I-cache, D-cache）
├─ 中断控制
├─ IPC通信区
└─ DMA描述符链（逻辑上独立）

共享资源（4个BBE共用）：
├─ DMAC PL080 (16个通道)
├─ AHB总线 (2个Master)
├─ SRAM控制器
├─ DRAM控制器
└─ 外设（UART、定时器等）

隔离性：
✓ 处理器核心独立 → 一个故障不影响其他
✓ 中断独立处理 → 各自可配置优先级
⚠ 总线共享 → 可能产生竞争（当前设计问题）
```

### 3.2 AHB总线架构（2个Master）

```
两路AHB Master的作用：

M1总线（低延迟）：
├─ 连接到: SRAM + RXC缓冲
├─ 特点: 低延迟 (~5-10ns)
├─ 使用者:
│  ├─ BBE#0 iDMA (src_ch0读取)
│  └─ BBE#1 iDMA (src_ch0读取，回退)
└─ 带宽: 32bit @ 100MHz ≈ 400MB/s

M2总线（标准延迟）：
├─ 连接到: DRAM + 外设
├─ 特点: 相对延迟 (~50-200ns)
├─ 使用者:
│  ├─ BBE#2 iDMA (src_ch2读取)
│  ├─ BBE#3 iDMA (src_ch2读取，回退)
│  └─ 输出缓冲写入 (chirp_buffer)
└─ 带宽: 32bit @ 100MHz ≈ 400MB/s

关键点：
✓ M1和M2可同时工作 → 400MB/s + 400MB/s
✗ 当前设计: 都在M1上竞争 → 产生瓶颈
```

## 4. 数据流和处理流程

### 4.1 完整的信号处理链

```
┌────────────────────────────────────────────────────┐
│ 第1步：天线接收                                    │
├────────────────────────────────────────────────────┤
│ 4路天线 → RF前端 → ADC                            │
│ └─ 时序: 连续采样 @ Fs (采样率)                 │
└────────────────────────────────────────────────────┘
             ▼
┌────────────────────────────────────────────────────┐
│ 第2步：接收链路缓冲                               │
├────────────────────────────────────────────────────┤
│ RXC0 (Antenna #0,#1) → src_ch0 (SRAM)            │
│ RXC1 (Antenna #2,#3) → src_ch2 (SRAM)            │
│ 问题❌：只有2条链路，4个BBE无独立源              │
└────────────────────────────────────────────────────┘
             ▼
┌────────────────────────────────────────────────────┐
│ 第3步：DMA传输                                     │
├────────────────────────────────────────────────────┤
│ DMAC读src_ch0/src_ch2 → 写chirp_buffer[j]        │
│                                                   │
│ BBE#0: DMA ch0-3   读src_ch0 → chirp_buf[0] ✓   │
│ BBE#1: DMA ch4-7   读src_ch0 → chirp_buf[1] ✗   │
│ BBE#2: DMA ch8-11  读src_ch2 → chirp_buf[2] ✓   │
│ BBE#3: DMA ch12-15 读src_ch2 → chirp_buf[3] ✗   │
│                                                   │
│ 圆形缓冲：每个BBE内部(dest_block_idx乒乓式)      │
│ 分层触发：数据层(链式) + 元数据层(独立)         │
└────────────────────────────────────────────────────┘
             ▼
┌────────────────────────────────────────────────────┐
│ 第4步：BBE处理 (4个并行)                          │
├────────────────────────────────────────────────────┤
│ BBE#0处理chirp_buf[0]：                          │
│ ├─ DMA读1024B数据块                             │
│ ├─ FFT变换                                       │
│ ├─ mag²计算 (功率谱)                             │
│ ├─ DMA写结果                                     │
│ └─ 元数据处理 + 中断                             │
│                                                   │
│ BBE#1/2/3：类似处理                              │
│ (但BBE#1和#3处理重复数据)                        │
└────────────────────────────────────────────────────┘
             ▼
┌────────────────────────────────────────────────────┐
│ 第5步：ARM后处理                                   │
├────────────────────────────────────────────────────┤
│ ARM M4读chirp_buffer中的结果                      │
│ ├─ 目标检测 (CFAR等)                            │
│ ├─ 距离估计                                      │
│ ├─ 速度估计 (多普勒)                            │
│ ├─ 信号融合 (4天线 但实际只有2个)             │
│ └─ 雷达输出                                      │
└────────────────────────────────────────────────────┘
```

### 4.2 时序图（单个Chirp处理周期）

```
时刻     事件
─────────────────────────────────────────────
T0      RXC0接收开始
        RXC1接收开始
        
T_rx    接收完成，数据写入src_ch0, src_ch2
        ↓
T_dma   DMA开始：
        ├─ BBE#0 DMA ch0: src_ch0 → chirp[0]
        ├─ BBE#1 DMA ch4: src_ch0 → chirp[1] (竞争M1)
        ├─ BBE#2 DMA ch8: src_ch2 → chirp[2]
        ├─ BBE#3 DMA ch12: src_ch2 → chirp[3] (竞争M1)
        
T_dma_end DMA完成，4个chirp_buffer都有数据
        ↓
T_fft   4个BBE同步启动FFT处理：
        ├─ BBE#0: chirp[0] → FFT → mag2[0]
        ├─ BBE#1: chirp[1] → FFT → mag2[1]
        ├─ BBE#2: chirp[2] → FFT → mag2[2]
        ├─ BBE#3: chirp[3] → FFT → mag2[3]
        
T_fft_end FFT处理完成
        ↓
T_irq   元数据DMA完成，产生中断
        ARM M4收集中断，处理结果
        
T_next  下一个Chirp周期开始
```

## 5. DMABufferConfigComplexMode的作用

### 5.1 函数在系统中的位置

```
ARM初始化流程：
1. DMAInit() → DMA硬件复位和配置
   
2. DMABufferConfigComplexMode() → 核心！
   ├─ 参数: bbe_id (0-3), fft_size
   ├─ 功能: 为指定BBE建立DMA描述符链
   │ ├─ 计算传输参数（圆形缓冲）
   │ ├─ 选择数据源（但BBE#1/3回退问题！）
   │ ├─ 生成数据描述符（分层触发第1层）
   │ ├─ 生成元数据描述符（分层触发第2层）
   │ └─ 形成闭合描述符链
   └─ 返回: 每Chirp的描述符数量

3. DMASetMode() → 设置DMA工作模式

4. DMAUpdateMode() → 激活配置
   ├─ SetRegDescStartAdrs() → 指向描述符缓冲
   └─ SetRegNumDescIncr() → 设置描述符数

5. DMAStart() → 启动DMA
```

### 5.2 为每个BBE配置的步骤

```
调用示例：
for (bbe_id = 0; bbe_id < 4; bbe_id++)
{
    DMABufferConfigComplexMode(bbe_id, 2048, &desc_per_chirp);
}

每次调用的内部流程：
┌─ 参数解析
├─ 传输参数计算
│  ├─ dma_level = 7
│  ├─ transfer_size = 1024字节
│  └─ transfer_block_qty = 4块
├─ 源地址选择 ⚠️ 问题在这里！
│  ├─ bbe_id=0 → src_ch0 ✓
│  ├─ bbe_id=1 → src_ch0 ✗ (回退)
│  ├─ bbe_id=2 → src_ch2 ✓
│  └─ bbe_id=3 → src_ch2 ✗ (回退)
├─ 描述符生成
│  ├─ 4个Chirp的数据描述符
│  └─ 4个元数据描述符
└─ 返回成功
```

### 处理吞吐量对比

```
场景1：理想配置（4个独立源）
─────────────────────────────
Chirp周期: T_chirp
BBE#0: src_ch0 → 处理 (时间: T_chirp)
BBE#1: src_ch1 → 处理 (时间: T_chirp, 并行)
BBE#2: src_ch2 → 处理 (时间: T_chirp, 并行)

────────────────────────────
总吞吐量 = 2 Chirps / T_chirp' ≈ 1.3-1.7x
利用率 = 50% (实际只有2组独立数据)

性能损失: ~65-70%
```

## 7. 改进方案

### SYSMEM映射实现

```
当前状态（缺陷）：
case 1:
    // Src address should be SYSMEM
    // src_addr = (Addr_t) (&src_ch1[0]);  ← 注释掉
    src_addr = (Addr_t) (&src_ch0[0]);    ← 临时回退

改进方案（完整）：
// mem.h中添加
extern int16_t src_ch1_sysmem[4][4096];  // DRAM
extern int16_t src_ch3_sysmem[4][4096];  // DRAM

// bbe_dma_adapter.c中修改
case 1:
    src_addr = (Addr_t) (&src_ch1_sysmem[0]);  // 真实源
    break;

case 3:
    src_addr = (Addr_t) (&src_ch3_sysmem[0]);  // 真实源
    break;

优点：
✓ BBE#1/3获得真实独立数据源
✓ M2总线承载更多负载
✓ 恢复完整的4x并行能力
✓ 减少M1总线竞争
```

## 结论

Surya SoC是一个专为雷达信号处理设计的异构SoC：
- ✅ **高性能DSP子系统**：4个Xtensa BBE处理引擎
- ✅ **高效DMA架构**：DMAC PL080 + 2路AHB + 圆形缓冲
- ✅ **灵活的分层触发**：支持链式同步和中断优化
- ⚠️ **设计缺陷**：SYSMEM映射未完成，BBE#1和#3无独立源
- 🔧 **改进方向**：完整实现SYSMEM支持，充分利用2个AHB Master

DMABufferConfigComplexMode函数是这个系统的核心配置接口，负责将逻辑的DMA操作具体化为硬件描述符链。
